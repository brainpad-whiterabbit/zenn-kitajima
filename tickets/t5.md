## Summary

人と AI が同じルールで記事を書けるように、リポジトリの構成と運用ルールを README と CLAUDE.md に書く。dgrelease と dgaudit は CLAUDE.md をリポジトリのルールとして読む。

CLAUDE.md に書く記事チケットの方針:
- Epic は 1 記事につき 1 つ（タイトルは「記事: <テーマ>」。説明には slug、想定読者、読後のゴール）
- チケットは PR 1 本で終わる工程ごとに切る（構成案 / 本文の執筆 / サンプルコードや図の作成と動作確認 / レビューの反映 / 公開）。規模に応じて統合や分割をしてよい
- 公開チケットは人が担当し、ほかの工程すべてに depends_on する。published を true にして main にマージする
- 記事を跨ぐ作業は記事の Epic に入れない
- Iteration の release は追加のリリース作業なしで、Iteration を閉じるだけ

## Acceptance criteria

- [ ] README に構成、slug 規則（YYYYMMDD-topic）、Publication（brainpad）、画像の置き場、プレビューと lint のコマンドが書かれている
- [ ] CLAUDE.md に上の記事チケットの方針が書かれている
- [ ] CLAUDE.md に「AI は published を true にしない」と書かれている
- [ ] CLAUDE.md に dgrelease が参照するリリース手順の節がある
